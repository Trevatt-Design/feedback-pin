# Design feedback

Design comments for this repo, pinned to the screens they are about. It runs on your machine while you develop and never ships in a build.

## Using it

Run the dev command as usual. The comment tool starts alongside it:

| Service | Address |
| --- | --- |
| Dashboard | http://localhost:8789 |
| Comment API | http://localhost:8787 |
| Widget script | http://localhost:8790/feedback-pin.js |

The first run installs the tool's own dependencies into this folder and takes about a minute. After that it starts in a few seconds.

Sign in to the dashboard with the project token printed in the terminal (`[feedback] comments on…`). Tokens are in `seed/manifest.json`. They only work against this local copy.

- **Website:** a Comment / Browse toggle sits at the bottom of every page. Click anything to pin a comment to it.
- **App:** the overlay button appears in development builds. It needs a simulator or emulator, because the overlay talks to `127.0.0.1`.

## What is already in it

The seed holds every design comment and review item raised so far, for the app and the website, with screenshots. `seed/manifest.json` lists the projects and counts.

On first run the seed is copied to `~/.feedback-pin/orbit`. Both Orbit repos use that folder, so app and website comments sit in one dashboard. Whichever repo starts first runs the servers; the other reuses them.

New comments stay in `~/.feedback-pin/orbit`. Delete that folder to go back to the seed.

## Switching it off

```sh
FEEDBACK_PIN=off npm run dev
```

It is also off whenever `CI` is set. If the tool fails to start, the dev command carries on without it. Logs are in `~/.feedback-pin/orbit/logs`.

## Updating

This folder is generated by `scripts/package-bundle.mjs` in the feedback-pin repo. Replace the whole folder rather than editing it here.
